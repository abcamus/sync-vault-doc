# Sync Vault 1+N 架构详解

在个人知识管理（PKM）领域，同步（Sync）始终面临着“不可能三角”的挑战：**速度、存储空间、安全性**。Sync Vault 通过独创的 **1+N 架构**，打破了这一僵局。

---

## 什么是 1+N 架构？

1+N 架构是一种**混合分布式同步模型**，它将传统的“中心化云存储”与现代的“点对点（P2P）协作”深度融合。

- **“1”：云端中心 (Source of Truth)**
  - 你的数据“大本营”。
  - 支持阿里云盘、百度网盘、OneDrive 等主流云存储。
  - **职责**：负责全量数据的长久保存、版本历史以及多端数据的最终对齐。
- **“N”：热节点 (Live Peers)**
  - 你的所有终端设备（电脑、手机、平板）。
  - **职责**：通过 P2P 协议（WebRTC）形成动态网络，实现秒级的实时感知与协作。

> [!abstract] 核心哲学
> **云端（1）负责持久化与容灾，设备间（N）负责极致的协作体验。**

## 核心技术支柱

### 1. VFS 虚拟化：网盘即硬盘
为了解决移动端存储瓶颈，Sync Vault 引入了**虚拟文件系统（VFS）**理念。

- **存根技术**：在同步时，设备端可以仅生成 `.osvc` 存根文件。这些文件仅占用几 KB 空间，却包含了文件的完整元数据。
- **按需补水**：只有当你点击查看或编辑某个文件时，系统才会从云端或 P2P 节点进行“补水（Hydration）”。
- **流媒体直达**：对于视频和音频文件，VFS 支持直接在线流式播放，无需下载整个文件即可在 Obsidian 内享受 4K 原画体验。
- **优势**：即使你的仓库有 1TB，在手机上依然可以秒速索引，且不占用磁盘空间。

### 2. P2P 实时协作：Obsidian 里的 Google Docs
在 1+N 架构下，当两个设备同时在线时，Sync Vault 会自动建立加密直连通道。

- **实时感官**：支持实时光标渲染，你可以清晰看到其他设备（或协作伙伴）的编辑轨迹。
- **冲突自愈**：采用 CRDT（无冲突复制数据类型）算法，多端编辑会像液体一样自动融合，传统的“冲突副本”文件已成历史。
- **零服务器中转**：协作数据仅在设备间流动，不经过任何云端服务器，极致私密且低延迟。

### 3. 端到端加密 (E2EE)
隐私是 Sync Vault 的底线。

- **云端加密**：数据在离开设备前即完成 AES-256 加密，网盘商无法窥视内容。
- **传输加密**：P2P 链路通过 DTLS 协议加密，数据不经过任何中转服务器。

## 为什么选择 1+N？

| 特性 | 传统同步 (iCloud/WebDAV) | Sync Vault 1+N |
| :--- | :--- | :--- |
| **同步速度** | 受限于网速与服务器响应 | **秒级 P2P 感知** |
| **存储占用** | 必须全量下载 | **VFS 按需加载 (零占容)** |
| **协作能力** | 容易产生冲突文件 | **实时协作，自动合并** |
| **数据主权** | 依赖特定服务商 | **网盘自由，端到端加密** |

## AI 时代的预备

1+N 架构原生集成了 **MCP Server (Model Context Protocol)**。

> [!tip] AI 燃料
> 传统的 AI 助手需要等待文件同步到本地才能读取。在 1+N 架构下，AI Agent 可以直接通过 MCP 接口访问云端（1）的全量数据。这意味着 AI 始终拥有你知识库的最全视图。

## 如何开启 1+N 体验？

1. **配置“1”**：在插件设置中绑定你的主云盘。
2. **连接“N”**：在多台设备安装插件并登录相同配置，开启「实时同步」。
3. **激活 VFS**：在移动端开启「虚拟文件系统」，享受无限空间的自由。
